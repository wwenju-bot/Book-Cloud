小说自动化创作平台

需求分析报告

面向业余写手的 AI 辅助创作解决方案

项目概述

本项目旨在依托 DeepSeek + 豆包 + 文件系统 Markdown 知识库 的技术组合，打造一套贴合业余写手创作习惯的自动化流程，从技术层面解决长篇创作的连贯性失控、逻辑矛盾、后续设定混乱三大核心痛点；产品化实现基于 Book-Cloud（RuoYi-Cloud）微服务框架二次开发，支持多用户使用，文件系统 Markdown 知识库内容可一键导出为 Obsidian 兼容格式。

核心价值

80% 效率提升

将“灵感→可连载的完整小说”的落地效率提升80%以上。

行业痛点分析

核心业务流程

1

项目初始化与资料上传

用户上传小说或输入灵感，配置全局参数。

2

DeepSeek 解析生成原始架构

调用模型，采用分层拆解策略生成结构化小说架构。

3

豆包 API 优化架构

结合用户规则，对架构进行多角度迭代优化。

4

逐章生成与优化

按优化架构产出章节初稿，经多模型优化后提交审核。

5

内容自动归档

审核通过的内容归档至平台文件系统 Markdown 知识库，可一键导出至 Obsidian。

核心功能模块

小说上传/灵感输入

支持上传已有小说文档或直接输入创作灵感，作为后续架构解析的基础数据。

架构解析模块 (DeepSeek)

将用户输入转化为结构化、可迭代的标准化小说架构，包含世界观、角色、剧情线等。

架构优化模块 (豆包)

调用豆包 API 优化完善原始架构，解决逻辑漏洞、节奏不合理、设定缺失等问题。

架构/章节审核模块

人工确认节点，用户确认架构和章节的创作方向、内容质量是否符合预期。

章节生成与多模型优化

基于审核通过的架构生成章节内容，调用多个模型并行完成多维度优化。

知识库归档与 Obsidian 导出

将审核通过的内容结构化归档到平台文件系统 Markdown 知识库，并支持一键导出为 Obsidian 兼容的 Markdown 包。

系统架构设计

基于 Book-Cloud（RuoYi-Cloud） 微服务框架二次开发，账号权限、网关、文件、任务调度等能力直接复用，仅新增创作业务与 AI 编排相关微服务。

前端层

管理端：Vue2 + Element UI (book-ui)

创作工作台：Vue3 + Vite（新建）

网关与治理层

book-gateway、book-auth

Nacos + Sentinel 服务治理

业务与 AI 编排层

book-novel（创作业务，新增）

book-ai（模型编排，新增）

数据与知识层

MySQL + Redis + MinIO + 向量库

文件系统 Markdown 知识库，一键导出 Obsidian

风险评估与解决方案

长文本解析与生成效果风险

模型上下文窗口限制、人设漂移、单一模型能力不足。

解决方案:

采用多模型混合编排，分块处理保留重叠内容，控制章节生成规模。

多模型调用融合效果风险

系统复杂度增加、风格不统一、成本超预期、选择困难。

解决方案:

统一选型规则，基准+补充融合策略，自动打分辅助决策，优化调用成本。

知识库导出与格式兼容风险

导出格式与 Obsidian 版本规范偏差、重复导出覆盖用户本地修改。

解决方案:

遵循 Obsidian 官方 Markdown 规范生成导出包，附带版本号与变更摘要，严格格式校验，完整导出日志。

API 调用稳定性与微服务治理风险

模型服务中断、响应超时影响流程稳定性。

解决方案:

AI 编排服务（book-ai）结合 Sentinel 设计限流、重试、熔断降级机制，友好提示用户。
